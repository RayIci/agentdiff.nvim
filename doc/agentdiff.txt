*agentdiff.txt*    Review the changes AI agents make, the way VS Code does

                                                    *agentdiff*

An AI agent (Claude Code, Copilot CLI, Codex, …) runs in another tmux pane
and writes straight to disk. agentdiff shows every one of those changes
inline as a pending diff that you can step through and keep or undo, per
change, per file or all at once. Edits you make in Neovim are never part of
the review. No agent needs any configuration; optionally, agent hooks can
report exactly which files they edit (|agentdiff-hooks|).

1. REQUIREMENTS                                *agentdiff-requirements*

- Neovim 0.12 or newer.
- `git` on `PATH`. It is used only as a content store in a private directory;
  the project doesn't have to be a git repository, and if it is, agentdiff
  never writes to its `.git`.
- No other plugins.

==============================================================================
2. SETUP                                              *agentdiff-setup*

>lua
    require("agentdiff").setup({
      keymaps = {
        next = "]a", prev = "[a",
        next_file = "]A", prev_file = "[A",
        keep = "<leader>rk", undo = "<leader>ru",
        keep_file = "<leader>rK", undo_file = "<leader>rU",
        keep_all = "<leader>ra", undo_all = "<leader>rA",
        panel = "<leader>rr", view = "<leader>rv",
        overlay = "<leader>rh", resolve = "<leader>rc",
      },
    })
<
No keymaps are created unless you pass them. `keep` and `undo` are also
mapped in visual mode, where they act on the selected lines.

Review starts on |VimEnter| for the project of the current directory: the git
toplevel, or the directory itself outside git. The home directory and `/` are
never used as a project unless you set `root`.

==============================================================================
3. OPTIONS                                          *agentdiff-options*

`attribution`    (string, default `"writer"`)
                 who changed a file: `"writer"` (anything Neovim didn't write
                 is the agent's) or `"hooks"` (only what an agent hook
                 reported). See |agentdiff-hooks|.

`keymaps`        (table|false, default `false`)
                 `action = lhs` pairs. Actions: `next`, `prev`, `next_file`,
                 `prev_file`, `keep`, `undo`, `keep_file`, `undo_file`,
                 `keep_all`, `undo_all`, `panel`, `view`, `overlay`,
                 `resolve`.

`poll_interval`  (integer, default `1000`)
                 ms between disk checks while Neovim is focused. `0` disables
                 the timer (detection then runs on focus, |BufEnter| and
                 `:Agentdiff refresh`).

`settle`         (integer, default `300`)
                 ms an unclaimed change waits before it is confirmed as the
                 agent's.

`claim_ttl`      (integer, default `10000`)
                 ms an unused claim stays valid.

`max_file_size`  (integer, default 1 MiB)
                 larger files are reviewed as whole files.

`max_files`      (integer, default `20000`)
                 projects with more files are not reviewed (with a notice).

`excludes`       (string[], default: build, cache and VCS directories)
                 gitignore-style patterns never reviewed, on top of the
                 project's `.gitignore` files.

`state_dir`      (string, default `stdpath("state") .. "/agentdiff"`)
                 where stores and the on/off state live.

`root`           (string, default: git toplevel or cwd)
                 force the project root.

`confirm`        (boolean, default `true`)
                 ask before keep-all / undo-all.

`keep_on_stage`  (boolean, default `true`)
                 staging a pending change in git (lazygit, `git add`,
                 `git commit -a`) keeps it, like VS Code. Unstaging never
                 makes anything pending again.

`hint`           (boolean, default `true`)
                 show the hint on the change nearest the cursor.

`auto_start`     (boolean, default `true`)
                 start on setup (on |VimEnter|).

4. REVIEWING                                      *agentdiff-reviewing*

When an agent changes a file, its buffer shows the change inline: removed
lines as virtual lines, added lines highlighted. The buffer text is the file
exactly as it is on disk; removed lines can't be edited or yanked.

The change nearest the cursor carries a hint with its position among all
pending changes and the keys that resolve it: >
    agent 2/5 · <leader>rk keep · <leader>ru undo
<
Keep~
    Accepts a change into the baseline. The file is not touched.

Undo~
    Restores the baseline content of a change, on disk. It goes through the
    file's buffer (loaded hidden when needed), so |u| afterwards brings the
    agent's change back as pending. When the buffer has unsaved edits of
    yours, the result stays unsaved with them until you write the buffer.
    Undoing a file the agent created deletes it; undoing a deletion restores
    the file. Windows are never closed: they show another buffer instead.

Scopes~
    the change under the cursor, the selected lines (visual mode or a
    range), the current file, or every file. Keep-all and undo-all ask
    first.

Editing~
    Typing anywhere is yours and never becomes pending. An edit inside a
    pending change becomes part of it: keep accepts your tweak, undo drops
    it. Writing the buffer never keeps agent changes.

Conflicts~
    When an agent writes a file whose buffer has unsaved edits of yours,
    non-overlapping changes are merged into the buffer (no prompt). When they
    overlap, the buffer is left alone and the file is marked conflicted.
    Keep accepts the agent's changes (the agent wins where it overlaps your
    unsaved edits, your other unsaved edits stay); undo rejects them (the
    disk goes back to the baseline, your unsaved edits stay). Either way the
    conflict ends and the buffer is in sync with the disk again.
    `:Agentdiff resolve` offers the same plus: take the agent's version
    outright (your edits are recoverable with |u|), or compare side by side.

Views~
    `:Agentdiff view` switches the current file between the inline overlay
    and a side-by-side diff against a read-only baseline window. Keep and
    undo work from either window. `:Agentdiff overlay` hides or shows the
    overlay without resolving anything.

5. COMMAND                                                *:Agentdiff*

:[range]Agentdiff [subcommand]

    Without a subcommand: toggle the panel. Subcommands complete with <Tab>.

    next / prev                 next / previous change, across files
    next_file / prev_file       next / previous changed file
    keep / undo                 the change under the cursor; with a range,
                                only the pending lines in it
    keep_file / undo_file       every change in the current file
    keep_all / undo_all         every change in every file (asks first)
    panel                       toggle the changed-files panel
    view                        toggle inline / side-by-side
    overlay                     hide / show the overlay
    resolve                     resolve a conflicted file
    refresh                     check the disk now
    reset                       forget the current project's pending
                                changes, start over from its files
    toggle / enable / disable   turn review on / off (persisted)
    status                      show the pending summary
    hooks [action] [harness] [scope]
                                manage agentdiff's hook in agent CLIs:
                                action `install`, `uninstall` or `status`
                                (default), harness `claude`, `copilot` or
                                `all` (default), scope `user` (default) or
                                `project`. See |agentdiff-hooks|.

==============================================================================
6. LUA API                                              *agentdiff-api*

All functions live on `require("agentdiff")`.

setup({opts})                                          *agentdiff.setup()*
    Configure; starts reviewing unless `auto_start = false`.

start() / stop()                         *agentdiff.start()* *agentdiff.stop()*
    Start or stop reviewing the current project, for this session only.

enable() / disable() / toggle()                       *agentdiff.toggle()*
    Turn review on or off, persisted across restarts and shared by every
    project. Turning it back on starts each project clean from its current
    files, so nothing changed while review was off is pending.

enabled()                                            *agentdiff.enabled()*
    True when review is on.

next() / prev() / next_file() / prev_file()           *agentdiff.next()*
    Navigation. `next()` past the last change of a file opens the next
    changed file; past the last change of the last file it wraps with a
    notice.

open({path})                                            *agentdiff.open()*
    Open a pending file at its first change.

keep({opts}) / undo({opts})              *agentdiff.keep()* *agentdiff.undo()*
    {opts} fields:
      `scope`  "hunk" (default), "file" or "all"
      `range`  { first, last } lines, with scope "hunk": only the pending
               lines in that range. Removed lines count as selected when the
               range starts at or above the change.
      `path`   project-relative file (default: the current buffer)
      `force`  with scope "all", skip the confirmation

keep_file() / undo_file() / keep_all({opts}) / undo_all({opts})
    Shorthands for the scopes above.

resolve({choice})                                    *agentdiff.resolve()*
    Resolve a conflicted file: "accept" (the agent's changes with your other
    unsaved edits on top), "agent", "mine" or "compare"; asks when nil.

panel() / toggle_view() / toggle_overlay()
    Views, see |agentdiff-panel| and |agentdiff-reviewing|.

reset({opts})                                          *agentdiff.reset()*
    Forget every pending change of the current project and start over from
    its current files. Other projects are untouched. Asks first unless
    `{ force = true }` or `confirm = false`.

claim({paths})                                         *agentdiff.claim()*
    The next disk changes to these paths (absolute or project-relative) are
    yours. For tools that write files directly. A directory claims every
    file under it. A claim is used up by the change it covers.

status()                                              *agentdiff.status()*
    Statusline summary such as `3 files · 7 changes`, or "" when nothing is
    pending.

files()                                                *agentdiff.files()*
    Pending files in navigation order: `path`, `status` ("modified",
    "created", "deleted", "binary", "conflicted"), `added`, `removed`,
    `hunks`.

path_status({path})                              *agentdiff.path_status()*
    "file" when the file has pending changes, "dir" when a directory
    contains such a file at any depth, nil otherwise. Cheap enough to call
    for every line of a file tree.

hooks_install({harness}, {scope})                  *agentdiff.hooks_install()*
hooks_uninstall({harness}, {scope})              *agentdiff.hooks_uninstall()*
    Add or remove agentdiff's hook in an agent CLI. {harness}: "claude",
    "copilot" or "all" (default); {scope}: "user" (default) or "project".
    Returns true on success. See |agentdiff-hooks|.

hooks_status({opts})                                *agentdiff.hooks_status()*
    Per harness: `installed`, `where` (configuration files holding the hook)
    and `last_report` (ms since the epoch of its newest report for the
    current project, or nil). Shown unless `{ silent = true }`.

==============================================================================
7. PANEL                                              *agentdiff-panel*

The panel lists every file with pending changes, its status letter (M
modified, A created, D deleted, B binary or oversized, C conflicted) and its
added/removed line counts, in navigation order.

    <CR>, o    open the file at its first change
    K / U      keep / undo the file under the cursor
    gK / gU    keep / undo everything
    R          check the disk now
    q          close

8. EVENTS AND STATUSLINE                             *agentdiff-events*

                                                   *User_AgentdiffChanged*
`User AgentdiffChanged` fires whenever the set of pending changes changes
(detected, kept, undone, resolved). Use it to refresh a statusline or a file
tree.

|agentdiff.status()| is a statusline component. With lualine: >lua
    sections = { lualine_x = { require("agentdiff").status } }
<

10. INTEGRATIONS                                *agentdiff-integrations*

Optional modules under `agentdiff.integrations`. agentdiff never loads them
itself, and they require the other plugin only when you call them, so
requiring one is safe even when that plugin isn't installed.

neo-tree.nvim~                               *agentdiff-integrations-neotree*
    A review mark (`󰚩`) on files with pending changes and on collapsed
    directories containing one, next to neo-tree's git marks: >lua
    local nt = require("agentdiff.integrations.neotree")
    require("neo-tree").setup({
      filesystem = {
        components = { agentdiff = nt.component },
        renderers = nt.renderers(),  -- neo-tree's defaults + the component
      },
    })
    nt.setup()                       -- refresh the tree on changes
<
    Change the mark with `nt.icon`; it uses |agentdiff-highlights|
    `AgentdiffTreeFile` and `AgentdiffTreeDir`.

oil.nvim~                                       *agentdiff-integrations-oil*
    Claim oil's file operations so renames, moves and deletes aren't the
    agent's: >lua
    require("agentdiff.integrations.oil").setup()
<
grug-far.nvim~                             *agentdiff-integrations-grug-far*
    Claim each file right before grug-far rewrites it: >lua
    require("grug-far").setup({
      hooks = {
        on_before_edit_file = require("agentdiff.integrations.grug_far").on_before_edit_file,
      },
    })
<
Other tools~
    Any tool that writes files itself can call |agentdiff.claim()| with the
    paths, before or right after writing.

11. WHO CHANGED WHAT                             *agentdiff-attribution*

Every file has a baseline: the last version you agreed with. Pending changes
are always baseline → current content.

- A change on disk that Neovim did not make, and that nobody claimed, is the
  agent's: the baseline stays, so the change becomes pending.
- Anything Neovim does is yours: typing, |:w|, format-on-save, LSP edits,
  shell commands run with |:!|, and tools that call |agentdiff.claim()|.
  Your edits are merged into the baseline too.
- Another Neovim instance on the same project: its writes are yours too.
- git operations (checkout, pull, reset, stash) that move HEAD: files git put
  back to HEAD's content are folded into the baseline.
- Discards (`git restore`, `git checkout -- f`, lazygit's file or hunk
  discard) only move a file toward its committed content: they are yours. An
  agent edit moves away from HEAD, so it stays pending.
- Staging keeps: staging a pending change (file or hunk) keeps it, as in VS
  Code, so a commit keeps what it stages. The same check runs when review
  starts, so changes committed while Neovim was closed are kept too; a
  deletion counts once the file is gone from the index and was tracked
  before. See `keep_on_stage`.

A newly seen, unclaimed change waits `settle` ms before it is confirmed as the
agent's, so claims from other instances can arrive first.

The above is the writer mode, the default. With `attribution = "hooks"`
(|agentdiff-hooks|), a change Neovim didn't make is the agent's only when an
agent hook reported the file; the git rules aren't needed then.

Agent hooks~                                             *agentdiff-hooks*

Claude Code and Copilot CLI can run a command before and after each tool
call. agentdiff's hook records the files their file tools edit, so the hooks
mode reviews exactly those and folds everything else into the baseline
(generators, build output, files created by other programs). Set it up once:
>lua
    require("agentdiff").setup({ attribution = "hooks" })
<
    :Agentdiff hooks install                 both CLIs, user scope
    :Agentdiff hooks install claude project  `.claude/settings.local.json`
    :Agentdiff hooks status                  where, and the last report

Configuration files written:

    claude   user: `~/.claude/settings.json`
             project: `.claude/settings.local.json`
             tools: Edit, Write, MultiEdit, NotebookEdit
    copilot  user: `~/.copilot/hooks/agentdiff.json`
             project: `.github/hooks/agentdiff.json`
             tools: edit, create, str_replace_editor, write, apply_patch

Install keeps your other settings and hooks, backs the original file up once
to `<file>.agentdiff.bak`, and changes nothing when already installed.
Uninstall removes only agentdiff's entries.

The hook runs `bin/agentdiff-hook.lua` with this Neovim (`-u NONE -l`, about
40 ms). It records the edit in the project's store, prints nothing and always
exits 0, so it never blocks or fails the agent's tool call, and it works
whether or not Neovim is running. The store location is written into the
hook command: install again after changing `state_dir` or moving the plugin.

A report matches a change when it was made within 10 s of the file's
modification time; it covers that one change. Agent edits made through shell
commands (`sed -i`, scripts) aren't reported and so aren't reviewed, as in
VS Code.

==============================================================================
12. THE STORE                                           *agentdiff-store*

Baselines live outside the project, one directory per project root, under
`stdpath("state")/agentdiff/`: a private git directory (objects only, never
committed to), `baseline.idx`, `observed.idx`, a `claims/` journal and a lock.
Every Neovim instance on the project shares it, and it survives restarts, so
pending changes are still there after |:restart| or a crash.

`:Agentdiff reset` (or |agentdiff.reset()|) forgets the current project's
pending changes. Deleting the store is always safe: agentdiff rebuilds it from the files on
disk, with nothing pending.

==============================================================================
13. LIMITATIONS                                   *agentdiff-limitations*

- In the writer mode, a program outside Neovim that isn't an agent (a build
  script in another pane, another editor) is shown as an agent change unless
  its output is ignored. Keep-file or keep-all dismisses it quickly; the
  hooks mode avoids it.
- In the hooks mode, agent edits made through shell commands aren't
  reviewed, and an agent CLI without an adapter isn't reviewed at all.
- Discarding unstaged changes while other changes to the same file are
  staged moves the file toward the index, not HEAD, and is shown.
- Files inside nested git repositories are not reviewed.
- Very large projects (more than `max_files` files) are not reviewed.
